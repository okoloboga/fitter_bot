# Анализ использования GPT Image моделей в CometAPI

## Ссылки на документацию
- **Документация CometAPI:** https://apidoc.cometapi.com/image-edits (ГЛАВНАЯ - проверять здесь!)
- **Документация OpenAI API:** https://platform.openai.com/docs/api-reference/images/createEdit (справочная, НЕ используется напрямую)
- **Страница модели CometAPI (подтверждает `gpt-image-1.5`):** https://www.cometapi.com/models/openai/gpt-image-1-5/

## ⚠️ ВАЖНОЕ ПРИМЕЧАНИЕ

**OpenAI API** и **CometAPI** - это разные сервисы:
- OpenAI API использует формат `multipart/form-data` и endpoint `/v1/images/edits`
- CometAPI использует формат Gemini API (JSON) и endpoint `/v1beta/models/{model}:generateContent`
- Текущая реализация работает через **CometAPI**, поэтому нужно проверять документацию CometAPI, а не OpenAI API

Подробное сравнение: см. `docs/OPENAI_VS_COMETAPI_ANALYSIS.md`

## 2. ENDPOINT И ФОРМАТ ЗАПРОСА

### Текущая реализация

**Файл:** `gpt_integration/photo_processing/image_client.py`

**Endpoint (строка 207):**
```python
endpoint = f"{self.base_url}/v1beta/models/{self.model}:generateContent"
```

**Формат запроса (строки 194-204):**
```python
body = {
    "contents": [
        {
            "role": "user",
            "parts": parts  # [{"text": prompt}, {"inline_data": {...}}, ...]
        }
    ],
    "generationConfig": {
        "responseModalities": ["TEXT", "IMAGE"]
    }
}
```

**Заголовки (строки 57-61):**
```python
headers={
    "Authorization": f"{self.api_key}",  # ⚠️ ВАЖНО: без "Bearer"
    "Content-Type": "application/json",
    "Accept": "*/*",
}
```

### Согласно документации CometAPI

**Проблема:** Не удалось получить прямой доступ к документации `https://apidoc.cometapi.com/image-edits` для проверки точного формата.

**Известная информация:**
- CometAPI является прокси-сервисом, который преобразует запросы
- Для Gemini моделей используется формат Gemini API
- Для GPT Image моделей может использоваться тот же формат (через прокси) или другой

**Актуальные endpoints для GPT Image моделей (CometAPI):**
1. **Text→Image**: `/v1/images/generations` (JSON)
2. **Image→Image (edits)**: `/v1/images/edits` (multipart/form-data)

### Параметры запроса

**Текущая реализация использует:**
- `contents` - массив с ролью и частями (текст + изображения)
- `generationConfig.responseModalities` - ["TEXT", "IMAGE"]

**Согласно документации GPT-Image-1:**
- Поддерживаются параметры:
  - `moderation`: `auto` (по умолчанию) или `low` - **НЕ ИСПОЛЬЗУЕТСЯ В ТЕКУЩЕЙ РЕАЛИЗАЦИИ**
  - Разрешения: 1024×1024, 1024×1536, 1536×1024 - **НЕ УКАЗЫВАЕТСЯ В ЗАПРОСЕ**

### Проблемы в текущей реализации

1. ⚠️ **Отсутствует параметр `moderation`** - может быть важен для фильтрации контента
2. ⚠️ **Не указывается разрешение изображения** - может быть важно для GPT Image моделей
3. ⚠️ **Используется формат Gemini API** - возможно, для GPT Image нужен другой формат
4. ⚠️ **Авторизация без "Bearer"** - может быть проблемой для некоторых моделей

## 3. ФОРМАТ ОТВЕТА

### Текущая реализация

**Парсинг ответа (строки 262-280):**
```python
candidates = data.get("candidates") or []
candidate = candidates[0]
content = candidate.get("content") or {}
parts = content.get("parts") or []

for part in parts:
    inline = part.get("inlineData") or part.get("inline_data")
    if inline:
        output_mime = inline.get("mimeType") or inline.get("mime_type") or "image/png"
        output_b64 = inline.get("data")
        break
```

**Формат:** Ожидается формат Gemini API с `candidates[0].content.parts[].inlineData.data`

### Потенциальные проблемы

Если GPT Image модели возвращают ответ в формате OpenAI API, парсинг может не работать:
- OpenAI формат: `data[0].url` или `data[0].b64_json`
- Gemini формат: `candidates[0].content.parts[].inlineData.data`
