# ЭТАП 2: AI-ПРИМЕРКА ОДЕЖДЫ

## ЦЕЛЬ ЭТАПА
Реализовать функционал виртуальной примерки одежды: пользователь загружает свое фото, система генерирует изображение с товаром на пользователе через Gemini API.

---

## 1. АРХИТЕКТУРА И ИНТЕГРАЦИИ

### 1.1 Новые компоненты

**GPT Integration Service (FastAPI):**
- Отдельный микросервис для работы с AI
- Валидация фото пользователя через ChatGPT
- Генерация примерок через Gemini API (CometAPI)
- Проверка контента на неприемлемость

**Хранилище фотографий:**
- Локальная файловая система
- Структура: `/storage/user_photos/{user_id}/` и `/storage/try_on_results/{user_id}/`

**Новые таблицы PostgreSQL:**
- `user_photos` - фотографии пользователей
- `try_on_history` - история примерок

### 1.2 API интеграции

**ChatGPT API (через OpenAI-совместимый endpoint):**
- Валидация фото: проверка наличия человека (минимум по пояс)
- Проверка на неприемлемый контент
- Возвращает структурированный JSON с результатом проверки и описанием проблем

**Gemini Image Generation API (через CometAPI):**
- Модель: `gemini-3-pro-image`
- Вход: до 3 изображений (фото пользователя + 2 фото товара) + текстовый промпт
- Выход: base64-encoded изображение (data URI)
- Timeout: 180 секунд

## 2. БАЗА ДАННЫХ

### 2.1 Таблица: user_photos

**Назначение:** Хранение фотографий пользователей для примерки

**Поля:**
- `id` - PRIMARY KEY
- `user_id` - FOREIGN KEY на users.id
- `file_id` - Telegram file_id (для ссылки на оригинал)
- `file_path` - путь к файлу на сервере
- `uploaded_at` - дата загрузки
- `is_active` - активно ли фото (булево)
- `consent_given` - дано ли согласие на обработку (булево)

**Ограничения:**
- Один пользователь может хранить максимум 3 фото
- При загрузке 4-го фото удаляется самое старое

### 2.2 Таблица: try_on_history

**Назначение:** История примерок для статистики и просмотра

**Поля:**
- `id` - PRIMARY KEY
- `user_id` - FOREIGN KEY на users.id
- `product_id` - ID товара из Google Sheets
- `user_photo_id` - FOREIGN KEY на user_photos.id
- `result_file_path` - путь к результату примерки
- `created_at` - дата создания
- `generation_time` - время генерации в секундах
- `status` - статус (success, failed, processing)

**Индексы:**
- INDEX на user_id, product_id для статистики популярности товаров

## 3. ФУНКЦИОНАЛ ПРИМЕРКИ

### 3.1 Загрузка фото пользователя

**Первая загрузка:**
1. Пользователь нажимает "👗 Примерить" в карточке товара
2. Если фото нет - запрашивается загрузка с объяснением требований
3. Пользователь должен дать согласие на обработку фото
4. Загружает фото (JPG/PNG, любого размера)

**Требования к фото:**
- Формат: JPG, PNG
- Максимум 10 МБ (если больше - автоматическое сжатие)
- Минимальное разрешение: 512x512 пикселей

**Обработка фото:**
1. Скачивание из Telegram
2. Проверка размера и формата
3. Сжатие если >10 МБ
4. Сохранение на сервер в `/storage/user_photos/{user_id}/`

### 3.2 Валидация фото через ChatGPT

**Процесс:**
1. Фото отправляется в ChatGPT с промптом валидации
2. ChatGPT проверяет:
   - Есть ли человек на фото (минимум по пояс)
   - Качество изображения (достаточная четкость)
   - Отсутствие неприемлемого контента
3. Возвращает JSON: `{valid: bool, reason: string, description: string}`

**Результаты валидации:**
- **Фото подходит:** сохранение в БД, переход к генерации
- **Фото не подходит:** пользователю отправляется понятное объяснение от ChatGPT, предложение загрузить другое фото
- **Неприемлемый контент:** отказ, сообщение о причине

### 3.3 Управление фотографиями

**Просмотр сохраненных фото:**
- В разделе "📐 Мои параметры" кнопка "📸 Мои фото"
- Отображаются все сохраненные фото (до 3 штук)
- Для каждого: превью, дата загрузки, кнопки "Использовать" и "Удалить"

**Выбор фото для примерки:**
- Если у пользователя уже есть фото - предлагается выбрать существующее или загрузить новое
- Пользователь видит превью всех своих фото
- Выбирает нужное для примерки

**Замена фото:**
- При загрузке нового фото (если уже 3 фото) - удаляется самое старое
- При загрузке запрашивается новое согласие на обработку

### 3.4 Генерация примерки

**Процесс:**
1. Пользователь выбирает фото и нажимает "Примерить"
2. Создается запись в `try_on_history` со статусом `processing`
3. Система собирает данные:
   - Фото пользователя (file_path)
   - 2 фото товара (photo_1_url, photo_2_url из Google Sheets)
   - Текстовый промпт (фиксированный)
4. Отправка запроса в GPT Integration Service → Gemini API
5. Ожидание генерации (~180 секунд, без промежуточных обновлений)
6. Получение результата (base64 data URI)
7. Сохранение результата на сервер в `/storage/try_on_results/{user_id}/`
8. Обновление записи в БД: статус `success`, `result_file_path`, `generation_time`

**Фиксированный промпт для Gemini:**
```
Создай реалистичное изображение, где человек с первого фото одет в одежду с других фото.
Сохрани черты лица, прическу и позу человека.
Одежда должна выглядеть естественно на фигуре с учетом складок и драпировки.
Сохрани фон из оригинального фото пользователя.
```

**Во время генерации:**
- Пользователь видит сообщение: "Создаем твою примерку... Это займет около 3 минут ⏳"
- Отменить процесс нельзя

**После успешной генерации:**
- Отправляется результат (изображение)
- Подпись: "Вот как на тебе будет смотреться [название товара]! 💫"
- Кнопки:
  - "🔗 Купить на WB"
  - "💾 Сохранить результат" (отправка как документ)
  - "🔄 Попробовать другое фото"
  - "👗 Примерить другой товар"
  - "◀️ Вернуться к товару"

**При ошибке генерации:**
- Запись в БД обновляется: статус `failed`
- Сообщение: "Не удалось создать примерку 😔 Попробуй загрузить другое фото или выбрать другой товар"
- Кнопки: "📸 Загрузить другое фото", "◀️ Вернуться к товару"

## 4. ИСТОРИЯ ПРИМЕРОК

### 4.1 Просмотр истории

**Доступ:**
- В главном меню появляется кнопка "📜 История примерок" (после первой примерки)
- Отображаются карточки с пагинацией (как товары)

**Карточка примерки:**
- Результат примерки (изображение)
- Название товара
- Дата примерки
- Кнопки:
  - "🔗 Купить на WB"
  - "💾 Скачать"
  - "🗑 Удалить из истории"

**Пагинация:**
- Аналогично каталогу товаров (◀️ / ▶️)
- Счетчик: "Примерка 3 из 15"
- Сортировка: от новых к старым

**Удаление из истории:**
- Запись удаляется из БД
- Файл результата удаляется с сервера
- Уведомление: "Примерка удалена"

## 5. ЛИМИТЫ И ОГРАНИЧЕНИЯ

### 5.1 Rate limiting

**Примерки:**
- Максимум 20 примерок в день на пользователя
- Подсчет: COUNT записей в `try_on_history` с `created_at >= TODAY`
- При превышении: "Ты достиг лимита примерок на сегодня (20/20). Попробуй завтра! 😊"

**Загрузка фото:**
- Без ограничений по количеству в день
- Ограничение только по хранению (максимум 3 фото)

### 5.2 Хранение данных

**Срок хранения:**
- Фото пользователей: пока пользователь не удалит или не заменит
- Результаты примерок: без ограничения срока (пока пользователь не удалит)

**Согласие на обработку:**
- Запрашивается при каждой загрузке нового фото
- Фиксируется в поле `consent_given` в таблице `user_photos`
- Текст согласия: "Для работы примерки нам нужно обработать твое фото с помощью AI. Мы сохраним фото для повторного использования. Фото используется только для примерки и не передается третьим лицам. Согласен(на)?"

## 6. АДМИНИСТРАТИВНАЯ ПАНЕЛЬ

### 6.1 Новая статистика в /admin_stats

**Примерки:**
- Всего примерок: `COUNT(*) FROM try_on_history WHERE status = 'success'`
- Примерок сегодня: с фильтром `created_at >= TODAY`
- Примерок за 7 дней
- Примерок за 30 дней
- Среднее время генерации: `AVG(generation_time) WHERE status = 'success'`
- Процент успешных: `(success / (success + failed)) * 100`

**ТОП товаров для примерки:**
- ТОП-5 товаров по количеству примерок: `GROUP BY product_id, COUNT(*) FROM try_on_history`

**Пользователи с фото:**
- Загрузили фото: `COUNT(DISTINCT user_id) FROM user_photos`

## 7. ИНТЕГРАЦИЯ С GPT INTEGRATION SERVICE

### 7.1 Архитектура

**GPT Integration Service:**
- Отдельный FastAPI микросервис (порт 9001)
- Авторизация через API ключ (`X-API-Key` header)
- Асинхронная обработка запросов

### 7.2 API endpoints

**POST /v1/photo/validate**
- Валидация фото через ChatGPT
- Вход: `{telegram_id, photo_file_id}`
- Выход: `{valid: bool, reason: string, description: string}`

**POST /v1/photo/process**
- Генерация примерки через Gemini
- Вход: `{telegram_id, photo_file_ids: [user_photo, product_photo_1, product_photo_2], prompt}`
- Выход: `{status: "success", result: {photo_url: "data:image/png;base64,...", processing_time: 145.2}}`

### 7.3 Обработка ошибок

**Timeout:**
- Если генерация превышает 180 секунд - ошибка timeout
- Возврат: `{status: "error", error_type: "timeout", message: "..."}`

**API errors:**
- Недоступность Gemini/ChatGPT API
- Возврат: `{status: "error", error_type: "api_error", message: "..."}`

**Processing errors:**
- Ошибки обработки изображений
- Возврат: `{status: "error", error_type: "processing_error", message: "..."}`
